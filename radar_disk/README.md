# radar — библиотека для сенсоров CC Optical (CC:Tweaked)

Содержимое дискеты:

| Файл | Назначение |
|---|---|
| `startup.lua` | Автозапуск при загрузке компьютера с дискетой: ставит или обновляет библиотеку, затем запускает собственные startup-файлы компьютера |
| `install.lua` | Установщик. `disk/install` ставит или обновляет, `disk/install remove` удаляет |
| `radar.lua` | Сама библиотека |
| `radarui.lua` | Экран радара для монитора, экрана компьютера или окна |
| `ballistics.lua` | Баллистический калькулятор для пушек CBC |
| `example_gun.lua` | Пример наведения пушки. Копируется в `/gun_example.lua`, если такого файла ещё нет |
| `loader.lua` | Ставится как `/startup/00_radarlib.lua` и делает `require("radar")`, `require("radarui")` и `require("ballistics")` доступными из любой папки |
| `example.lua` | Пример. Копируется в `/radar_example.lua`, если такого файла ещё нет |
| `example_ui.lua` | Пример экрана радара. Копируется в `/radar_ui_example.lua`, если такого файла ещё нет |

## Установка одной командой (нужен HTTP в CC)

```
wget run https://raw.githubusercontent.com/cfifskin/radarLib/main/radar_disk/get.lua
```

Команда скачивает файлы из репозитория во временную папку, устанавливает библиотеку и удаляет временные файлы. Перезагрузка не нужна.

Сделать установочную дискету (файлы останутся на ней):

```
wget run https://raw.githubusercontent.com/cfifskin/radarLib/main/radar_disk/get.lua disk
```

## Установка с дискеты

1. Скопируйте файлы этой папки на дискету: в мире это `saves/<мир>/computercraft/disk/<id>/`, где `<id>` выдаёт команда `id` при вставленной дискете.
2. Вставьте дискету в дисковод рядом с компьютером.
3. Перезагрузите компьютер (зажать **Ctrl+R**) или выполните `disk/install`.

Сама по себе вставка дискеты в уже работающий компьютер ничего не запускает: CC:Tweaked выполняет `startup` с дискеты только при загрузке.

## Использование

```lua
local radar = require("radar")
local sensor = peripheral.find("entity_radar")

local targets, info = radar.scan(sensor, "sublevel")                    -- один тип, локальные координаты
local targets, info = radar.scan(sensor, { "sublevel", "object_large" }) -- несколько типов
local targets, info = radar.scan(sensor, nil, true)                     -- все цели, мировые координаты
```

### `radar.scan(sensor, filter, global)`

- `sensor`: обёрнутая периферия (`peripheral.find(...)`/`peripheral.wrap(...)`) или её имя. Подходит любой сенсор ccoptical.
- `filter`: тип строкой, список типов или `nil`/`{}`, если фильтр не нужен. Регистр не важен.
- `global`: `true` даёт мировые координаты, `false`/`nil` даёт смещение от центра блока сенсора по осям мира. По умолчанию `false`.

Функция возвращает `targets, info`.

Поля каждой цели в `targets`:

| Поле | Описание |
|---|---|
| `uuid` | UUID цели: у сущности — её UUID, у конструкции Sable — UUID конструкции |
| `type`, `name`, `subLevelName` | Как в ccoptical (`name` — только у игроков вблизи, `subLevelName` — у конструкций) |
| `subLevelUUID` | Только у сущности, которая находится на конструкции: UUID этой конструкции. У самой конструкции поля нет, её UUID лежит в `uuid` |
| `x`, `y`, `z` | Сглаженная позиция, округлена до 0.01 |
| `distance` | Расстояние от ccoptical (у мода оно без шума), округлено до 0.01 |
| `velocity` | `{x, y, z}`, вектор скорости в блоках за тик, округлён до 0.001 |
| `speed` | Модуль скорости в блоках за тик |
| `samples` | Сколько сканов усреднено в этой позиции (обычно `config.scans`) |
| `tracked` | Сколько тиков цель уже отслеживается. При `tracked == 0` скорость ещё равна 0 |

`info` = `{ sensor, tick, total, scans, global, mode, origin, range, orientation }`. `total` — число целей до фильтра, `scans` — сколько сканов удалось сделать, `origin` — позиция сенсора при `global = true`, `mode` — способ, которым она получена (см. ниже), `range` — дальность сенсора (`getRange()`, с учётом усилителей), `orientation` — кватернион `{x, y, z, w}` конструкции Sable, если компьютер стоит на ней.

### Позиция радара (для мировых координат)

Мод отдаёт только смещение цели от сенсора, поэтому библиотеке нужна мировая позиция самого сенсора. Обычно достаточно одной строки:

```lua
radar.setOffset(sensor, dx, dy, dz)   -- блок радара минус блок компьютера
```

Этот вызов работает одинаково на земле и на конструкции Sable. Библиотека сама определяет, где стоит компьютер, через `sublevel.isInPlotGrid()` из CC: Sable.

| Режим (`info.mode`) | Когда | Как считается позиция радара |
|---|---|---|
| `"ground"` | компьютер на земле | Блок компьютера по GPS (один раз) + смещение. Оси смещения — оси мира |
| `"structure"` | компьютер на конструкции Sable | Один раз калибруется блок компьютера в координатах конструкции (GPS + поза). Дальше каждый скан: поза из `sublevel.getLogicalPose()`, к ней применяется смещение. Оси смещения — сетка блоков самой конструкции, поэтому при любом движении и повороте оно остаётся верным |
| `"manual"` | задан `radar.setOrigin` | Фиксированные координаты блока радара (F3). Только для земли, GPS не нужен |

Как получить смещение на конструкции: посчитайте блоки от компьютера до радара вдоль самой конструкции (вправо/вверх/вперёд в её осях). Удобнее сделать это до сборки, когда оси конструкции совпадают с осями мира: тогда это просто разность координат F3.

Требования и тонкости:
- Нужен беспроводной модем на компьютере и настроенные GPS-хосты (`gps host x y z` с координатами блока компьютера-хоста). GPS измеряет позицию блока, к которому прикреплён модем. Обычно это сам компьютер, от него и отсчитывается смещение.
- На конструкции после калибровки GPS больше не используется. Калибровка проверяет, что конструкция не сдвинулась заметно, пока GPS ждал ответов. Если она двигалась быстро, будет ошибка `structure calibration failed`. Тогда замедлите конструкцию и вызовите `radar.calibrate()`.
- Компьютер и радар должны стоять на одной конструкции (или оба на земле).
- `radar.getOrigin(sensor)` возвращает `{x, y, z}, mode`. Удобно для проверки: сравните результат с F3, наведя прицел на радар.
- `radar.calibrate()` заново измеряет позицию компьютера (например, после его переноса).

### Прочее

- `radar.reset(sensor)` забывает накопленные цели, и скорость начинает считаться заново.
- `radar.config` хранит настройки: `decimals`, `velocityDecimals`, `scans`, `velocityWindow`, `maxGapTicks`, `gpsTimeout`, `structureCheck` (как часто, в секундах, проверять, стоит ли компьютер на конструкции: каждый вызов CC: Sable стоит тик).

## Экран радара (`radarui`)

```lua
local radar = require("radar")
local ui = require("radarui")
local sensor = peripheral.find("entity_radar")
local monitor = peripheral.find("monitor")

local function radarLoop()
    while true do
        local targets, info = radar.scan(sensor, nil, true)
        local selected = ui.draw(monitor, targets, info, "-z", true, true)
        sleep(0.25)
    end
end

parallel.waitForAny(radarLoop, ui.listen) -- ui.listen нужен только для выбора касанием
```

### `ui.draw(device, targets, info, front, showInfo, touch)`

- `device`: монитор (обёрнутый или его имя), `term.current()` или окно `window`.
- `targets`, `info`: результат `radar.scan`.
- `front`: ось, которая смотрит вверх экрана: `"x"`, `"-x"`, `"z"`, `"-z"`. Если компьютер стоит на конструкции Sable, это оси самой конструкции, и картинка поворачивается вместе с ней (учитывается только курс, крен и тангаж игнорируются).
- `showInfo`: `true` — справа панель с выбранной целью, `false` — только круг по центру.
- `touch`: `true` — касание цели на продвинутом мониторе выбирает её, касание пустого места в круге снимает выбор.

Функция возвращает выбранную цель из `targets` (или `nil`).

Что на экране:
- Круг — дальность сенсора (`info.range`), центр — сенсор, серое кольцо — половина дальности, зелёная риска сверху — направление `front`.
- Цели — вид сверху: горизонтальное смещение от сенсора в масштабе дальности. Цвет по типу: `sublevel` — оранжевый, `object_large` — красный, `object_mid` — жёлтый, `object_small` — салатовый, цели с именем (игроки) — голубые.
- Выбранная цель отмечена белыми стрелками по бокам (`►■◄`, одна строка в высоту), голубая линия — куда она сместится за 1 секунду.
- Панель: UUID, имя, тип, координаты (мировые при `global = true`, иначе смещение), дистанция, скорость в блоках/тик и блоках/сек. Ушедшая с радара цель показывается как `TARGET LOST`.

Масштаб подбирается сам: для монитора выбирается наибольший размер текста, при котором остаётся не меньше 50×20 символов. Монитор 3×2 блока получает масштаб 0.5 (57×24 символов), 6×4 — масштаб 1, 9×6 — 1.5, картинка одна и та же. При изменении размера монитора всё пересчитывается. Круг рисуется символами телетекста (2×3 квадратных пикселя на символ), поэтому он круглый.

### Выбор цели

```lua
ui.select(monitor, target.uuid)              -- или ui.select(monitor, target); nil снимает выбор
local uuid, target = ui.getSelected(monitor) -- target = nil, если цели сейчас нет на радаре
```

Выбор касанием делает то же самое, что `ui.select`. Чтобы касания обрабатывались, рядом с циклом радара должен работать `ui.listen` (через `parallel`, как в примере). Если у вас свой цикл событий, вызывайте в нём `ui.handleEvent(os.pullEvent())`.

`ui.config` хранит настройки: `textScale` (зафиксировать масштаб), `minWidth`/`minHeight`, `infoWidth`, `touchRadius`, `velocitySeconds`, `colors`.

На мониторе нет кириллицы (шрифт CC), поэтому подписи на экране — латиницей.

## Баллистический калькулятор (`ballistics`)

Считает, как навести лафет CBC, чтобы попасть в цель с учётом её движения, положения и поворота конструкции Sable и скорости самой конструкции. Физика повторяет код модов: Create Big Cannons 5.11, CBC: Enhanced Shells, CBC: Advanced Technology.

```lua
local radar = require("radar")
local ballistics = require("ballistics")

local CANNON_OFFSET = { 2, 0, -3 }   -- блок лафета минус блок компьютера (как у радара)

local gun = ballistics.bigCannon({
    offset = CANNON_OFFSET,          -- эту таблицу может менять другой скрипт, читается при каждом aim
    length = 8,                      -- блоков пушки перед затвором, до дула включительно
    muzzle = 5,                      -- блоков от блока над лафетом до дульного блока
    charges = { "powder", "powder", "mk3" }, -- заряды от затвора вперёд
    shell = "he_shell",
})
local solution = gun:aim(target, { arc = "auto" })  -- target из radar.scan(..., true)
if solution.ok then ballistics.point(mount, solution) end
```

Конструкторы:

| Функция | Параметры |
|---|---|
| `ballistics.bigCannon{...}` | `offset`, `length`, `muzzle`, `charges`, `shell`, `muzzleBrakes` (дульные тормоза CBC: AT в конце ствола), `speed` (задать скорость вручную) |
| `ballistics.autocannon{...}` | `offset`, `material` (`"cast_iron"`, `"bronze"`, `"steel"`), `barrels` (блоков автопушки перед затвором), `muzzle`, `round` |
| `ballistics.heavyAutocannon{...}` | то же, что у автопушки, плюс `strong = true` для усиленного патрона (×1.5 к скорости) |

Общие параметры: `limits = {мин, макс}` — пределы наклона (по умолчанию −30..60 у big cannon, −45..90 у автопушек), `pivotOffset` — где ось поворота относительно блока лафета (по умолчанию `{0, 1, 0}`, блок над лафетом).

Заряды: `"powder"` (порох CBC, 2), `"mk1"`…`"mk5"` (CBC: ES, 2.5…4.5), `"cartridge1"`…`"cartridge4"` (большая гильза, 2 за уровень) или число. Снаряды: все снаряды CBC и CBC: ES, варианты Mk пишутся как есть (`"he_shell_mk3"`). У ES bunker buster своя баллистика, остальные Mk совпадают с базовыми. Патроны автопушки: `ap`, `flak`, `machine_gun`, `apds`, `apdsfs`, `he`, `hei`. Тяжёлой: `ap`, `apds`, `apdsfs`, `he`, `hef`, `heat`, `smoke`. Можно передать свою таблицу `{gravity = , drag = , quadratic = }`.

`gun:aim(target, opts)` возвращает таблицу:
- `ok`, при неудаче `reason` (`out of range`, `pitch ... outside ...`, `projectile expires ...`);
- `yaw`, `pitch` — углы лафета в градусах в его собственной системе: на конструкции это оси конструкции. Соглашение CBC: yaw 0 = +Z, 90 = −X, 180 = −Z, pitch > 0 — вверх;
- `worldYaw`, `worldPitch`, `direction` — направление ствола в мире;
- `ticks` — время полёта, `aimPoint` — где будет цель в момент попадания, `muzzle` — точка вылета снаряда, `carrierVelocity` — скорость, которую снаряд наследует от конструкции.

`opts.arc`: `"low"` (по умолчанию), `"high"` (навесная) или `"auto"` (настильная, а если она за пределами наклона — навесная). `opts.latency` — сколько тиков пройдёт до выстрела (цель упреждается и на это время).

`ballistics.point(mount, solution)` поворачивает лафет. Поддерживаются периферии `cannon_mount` (CC:CBC, плавный поворот через `setTargetAngles`) и `cbc_cannon_mount` (CBC Peripheral, мгновенно через `setYaw`/`setPitch`). `gun:trajectory(solution)` даёт точки полёта по тикам.

Что учитывается:
- Начальная скорость big cannon. В CBC это сумма сил зарядов. CBC: AT по умолчанию заменяет её своей моделью «газов»: каждый блок ствола добавляет скорость и сопротивление, поэтому скорость зависит от длины пушки и от положения зарядов (`ballistics.bigCannonSpeed{...}` её считает). Если на сервере в конфиге cbc_at `disablePhysicRework = true`, поставьте `ballistics.config.physicsRework = false`.
- Скорость автопушки: `base_speed + speed_increase_per_barrel × min(стволы, max_speed_increases)` материала. Снаряд живёт `projectile_lifetime` тиков (у тяжёлой ×3), за этим пределом решения нет.
- Полёт: каждый тик `позиция += v + a/2`, `v += a`, где `a = гравитация − drag·v` (у тяжёлой автопушки `drag·|v|·v`). Для линейного сопротивления решение точное (замкнутая формула), для квадратичного — итерации Ньютона по симуляции.
- Точка вылета: у big cannon центр дульного блока, у автопушки — передняя грань последнего ствола.
- Конструкция Sable: углы пересчитываются в оси конструкции, а скорость точки вылета (`sublevel.getVelocity` + вращение) прибавляется к скорости снаряда, как делает CBC при `sableProjectilesInheritPhysicsObjectVelocity = true` (по умолчанию). Если на сервере выключено — `ballistics.config.inheritVelocity = false`.

Позиция пушки, как и радара, считается от компьютера через `radar.blockToWorld`: на земле нужен GPS или `radar.setHost(x, y, z)` (координаты блока компьютера), на конструкции — GPS для калибровки.

Не учитывается: случайный разброс выстрела, вода на пути, лафеты вверх ногами, минометы, ракеты и ракетные установки, спаренные автопушки. Проверить калькулятор в игре стоит выстрелом по неподвижной цели: если промах заметный, сверьте `length`, `muzzle` и конфиги сервера.

## Как работает подавление шума

Радар добавляет к каждой координате гауссов шум с σ = (0.45 + 0.02·дистанция) × множитель высоты. Около уровня моря множитель ≈ 1, выше полосы у моря он падает до 0.2. На 64 блоках σ ≈ 1.7 блока.

**Позиция.** Каждый вызов `radar.scan` делает `config.scans` сканов сразу (по умолчанию 4). Они запускаются параллельно, поэтому CC выполняет их в одном игровом тике, и у каждого свой независимый шум (мод берёт его из `level.random`). Позиция — среднее этих сканов, без старых данных, поэтому она не отстаёт от цели и не «догоняет» её после остановки. Шум уменьшается в √4 = 2 раза: на 64 блоках ошибка по оси ≈ 0.85 блока вместо 1.7. Если сервер не успел выполнить все сканы в одном тике, поздние замеры приводятся к последнему тику по скорости цели.

**Скорость.** Наклон прямой (МНК) по позициям цели за последние `config.velocityWindow` тиков (по умолчанию 20 = 1 секунда), каждая позиция с весом числа сканов. Для этого используются только позиции, сама позиция от истории не зависит. У оптических сенсоров шума нет, у них скорость — разность двух последних позиций.

Проверка на модели (σ = 1.7, цель проходит 64 блока за 2 секунды и резко останавливается, `radar.scan` + `sleep(0.25)` = вызов раз в 6 тиков):

| | результат |
|---|---|
| ошибка позиции (3D, RMS) | 1.28 блока, без отставания |
| скорость на 1.6 бл/тик (32 бл/с) | 1.48 на втором вызове, далее 1.5–1.7; среднее 1.600 |
| после остановки | скорость ≈ 0 через ~1 секунду (длина окна) |
| шум скорости у стоящей цели | 0.06 бл/тик (1.3 бл/с) |

Компромиссы настраиваются: больше `scans` — точнее позиция (ошибка ∝ 1/√scans), но больше нагрузка на сервер; меньше `velocityWindow` — скорость быстрее реагирует на манёвр, но шумнее (шум ∝ окно^−1.5). Чем чаще вызывать `scan` и чем выше поставить радар, тем точнее оценки. На первом вызове после появления цели скорость равна 0 (`tracked == 0`).

В режиме `global = false` при движущемся сенсоре скорость получается относительной (цель минус сенсор). При `global = true` скорость абсолютная, в том числе когда радар стоит на летящей конструкции.

## Ограничения

- Чтобы `require` работал из любой папки, загрузчик регистрирует модуль в `debug.getregistry()._LOADED`. CC:Tweaked (проверено на 1.117.1 и 1.120.0) копирует эту таблицу в `package.loaded` каждой программы. Это внутренняя деталь CC:Tweaked, и в будущих версиях она может измениться. Тогда загрузчик выведет подсказку, а в программе нужно будет добавить строку `package.path = "/lib/?.lua;" .. package.path`.
- Библиотеки загружаются один раз при старте компьютера. После обновления `/lib/radar.lua` или `/lib/radarui.lua` нужна перезагрузка.
- Пока дискета вставлена, её `startup` заменяет startup компьютера. Скрипт с дискеты сам запускает `/startup.lua` и `/startup/*`, но после установки дискету лучше вынуть.
